Documented gaps (test.fixme) — 2 scenarios × 3 browsers

  • App Store / Google Play download links. Confirmed (via the app's own i18n bundle keys "app-store"/"google-play" under "trade-on-the-go") to live only on the authenticated homepage template. Unreachable without logging in, which the brief explicitly disallows.
  • About Us > Why MultiBank page. Same gated-homepage constraint; no standalone public route exists today (/about-us, /why-multibank, /about-us/why-multibank all return 404).

Real findings surfaced during verification (not test defects — see docs/RISK_MATRIX.docx)

  1. Loading-skeleton race condition (fixed in the suite). /markets briefly renders a loading skeleton with different header copy and column counts before hydrating; "Favorites" additionally uses a permanently different column schema, and mobile viewport collapses columns further. Headless execution usually outran this; headed/slower execution caught it. Fixed by waiting on hydrated "$"-priced row content rather than any specific header label.
  2. Trade-menu link href briefly empty under heavy concurrent load. Observed once across 5 parallel workers × 3 browsers; not reproducible in 10/10 isolated attempts. Hardened the assertion to wait for a non-empty href first; CI's retry policy (2 retries) also absorbs this class of transient noise.
  3. Live Cloudflare 502 from trade.mb.io hit once mid-verification (real production infrastructure blip, confirmed via the actual Cloudflare error page content, resolved within seconds). Not a suite defect — evidence the target is a live third-party system, which is exactly why CI runs with retries.
